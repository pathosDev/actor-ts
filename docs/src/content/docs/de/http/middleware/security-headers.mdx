title: Security-Header
description: securityHeaders() ist ein kleines Helmet-artiges Bündel (nosniff, X-Frame-Options, Referrer-Policy, COOP/CORP, …), jeder Header überschreibbar oder weglassbar. strictTransportSecurity() sendet HSTS.
---

`securityHeaders()` ergänzt ein sinnvolles Set an Security-Response-Headern.
Jeder Header ist einzeln überschreibbar, `false` lässt einen weg, und ein
vom Handler bereits gesetzter Header gewinnt immer.

Abgedeckt ist der gesamte Teilbaum, Ablehnungen eingeschlossen: Eine
Schicht darunter, die per `HttpError` kurzschließt — CSRF, Auth, ein
Rate-Limit —, erzeugt eine Response, die die Header ebenfalls trägt.

<Aside type="caution" title="`false` lässt einen Header weg, es entfernt ihn nicht">
  Das Bündel **ergänzt** nur. Als Middleware läuft es auf dem auf, was das
  Backend ohnehin schreibt — `false` heißt also "diese Middleware fügt ihn
  nicht hinzu", nicht "diese Response trägt ihn nicht".

  Sichtbar wird der Unterschied heute an genau einer Stelle.
  `X-Content-Type-Options: nosniff` schreibt jedes Backend vor jede Response,
  die es ausliefert; `securityHeaders({ contentTypeOptions: false })` lässt
  den Header also stehen. Um ihn nicht mehr zu senden, ersetzt du die
  Defaults des Backends serverweit:
  `newServerAt(…).withSecurityHeaders({ contentTypeOptions: false })` — oder
  `withSecurityHeaders(false)` für gar keinen davon.

  Ein Opt-out pro Teilbaum gibt es bewusst nicht: Die Kopie des Backends hat
  das letzte Wort, gerade damit auch die Responses abgedeckt sind, die nie
  eine Middleware sieht — die backend-eigenen 404s, die Body-Parse-413s und
  die generische 500, auf die ein unbehandelter Wurf gemappt wird.
</Aside>

```ts
import { securityHeaders, withMiddleware } from 'actor-ts/http';

const routes = withMiddleware(securityHeaders(), appRoutes);
```

Defaults: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`,
`Referrer-Policy: no-referrer`, `Cross-Origin-Opener-Policy: same-origin`,
`Cross-Origin-Resource-Policy: same-origin` und `X-XSS-Protection: 0` (der
Legacy-Filter ist fehlerhaft — aus ist am sichersten). COEP,
Permissions-Policy und HSTS sind opt-in.

## Konfiguration

| Builder-Methode | Default |
| --- | --- |
| `withContentTypeOptions(flag?)` | `nosniff` an |
| `withFrameOptions('DENY' \| 'SAMEORIGIN' \| false)` | `'DENY'` |
| `withReferrerPolicy(value \| false)` | `'no-referrer'` |
| `withCrossOriginOpenerPolicy(v \| false)` | `'same-origin'` |
| `withCrossOriginResourcePolicy(v \| false)` | `'same-origin'` |
| `withCrossOriginEmbedderPolicy(v \| false)` | `false` (bricht Embeds; opt-in) |
| `withPermissionsPolicy(map \| false)` | `false` |
| `withHsts(options \| false)` | `false` (opt-in) |

```ts
const options = SecurityHeadersOptions.create()
  .withFrameOptions('SAMEORIGIN')
  .withHsts({ maxAge: 31_536_000, preload: true });
```

CSP ist bewusst **nicht** Teil des Bündels — es ist zu app-spezifisch;
konfiguriere es mit [`contentSecurityPolicy`](/de/http/middleware/csp/).

## HSTS allein — `strictTransportSecurity`

```ts
import { strictTransportSecurity, HstsOptions, withMiddleware } from 'actor-ts/http';

const hsts = strictTransportSecurity(
  HstsOptions.create().withMaxAge(31_536_000).withIncludeSubDomains().withPreload(),
);
```

Defaults: `max-age` 180 Tage + `includeSubDomains`. Der Header wird
bedingungslos gesetzt — ein Browser ignoriert ihn über reines HTTP, ein
Dev-Server ist also ein harmloser No-op, und Framework-Server sitzen ohnehin
meist hinter einem TLS-terminierenden Proxy.

### Aus der Konfigurationsdatei

Jedes Feld der Policy hat auch einen Key in `actor-ts.http.hsts` —
`max-age` (in Sekunden, eine blanke Ganzzahl), `include-sub-domains` und
`preload`. Was `hsts(options)` im Code nennt, gewinnt pro Feld, dann der
Block, dann der eingebaute Default, und die gemergte Policy wird einmal
validiert, wenn `bind()` den Route-Baum kompiliert:

```hocon
actor-ts.http.hsts {
  max-age = 63072000     # seconds — two years, not a duration string
}
```

`max-age = 0` wird dort mit einem `ConfigError` abgelehnt: Es würde jeden
Client jeder `hsts()`-Route im Prozess entpinnen, HSTS abschalten bleibt also
dem Code vorbehalten (`withMaxAge(0)`). Die Keys und ihre Defaults stehen in
[Konfiguration → `actor-ts.http`](/de/reference/configuration/).

Der Block erreicht `hsts()` über einen Hook, den `compile()` auflöst — gib die
Middleware also so, wie sie ist, an `withMiddleware(...)`. In eine eigene
Funktion verpackt — `(request, next) => hsts()(request, next)` — ist sie für
`compile()` unsichtbar und sendet die Code-Optionen über den eingebauten
Defaults.

### Zwei Wege zum Header

HSTS erreicht eine Response auf einem von zwei Wegen, und der Block steuert nur
einen davon:

| Weg | Konfiguriert aus |
| --- | --- |
| `hsts()` / `strictTransportSecurity()` | Code-Optionen, dann `actor-ts.http.hsts`, dann der eingebaute Default |
| das `hsts`-Feld von `securityHeaders()` und von `withSecurityHeaders(...)` | nur Code |

Wo beide den Header senden, gewinnt die Routenebene. Eine Middleware
überschreibt nie einen Header, den die Response schon trägt; von den
Middlewares auf Routenebene setzt ihn also die, die dem Handler am nächsten
ist, und die serverweite Map von `withSecurityHeaders(...)` wird unter das
geschrieben, was die Response trägt. Eine Route unter `hsts()` bekommt die
konfigurierte Policy also auch auf einem Server, dessen
`withSecurityHeaders({ hsts })` eine andere nennt, und nur die Responses, die
kein HSTS auf Routenebene erreicht — der eigene 404 des Backends, ein
Body-Parse-413 —, tragen die serverweite Policy.

<Aside type="caution" title="preload ist eine Verpflichtung">
  `withPreload()` erfordert `maxAge ≥ 1 Jahr` + `includeSubDomains` (die
  hstspreload.org-Regeln). Geprüft wird auf der gemergten Policy, das Jahr
  darf also aus `actor-ts.http.hsts` kommen; eine Policy, die ihr `preload`
  trotzdem nicht tragen kann, lässt `bind()` mit einem `OptionsError`
  scheitern. Eine Aufnahme in die Preload-Liste ist schwer rückgängig zu
  machen; stelle sicher, dass zuerst jede Subdomain HTTPS ausliefert.
</Aside>

## Über einer WebSocket-Route

`securityHeaders()` darf eine `websocket()`-Route umschließen wie jede
andere — das Upgrade kommt zustande.  Dekoriert wird dort die
**Ablehnung**: Ein Handshake, den eine innere Auth-Middleware abweist,
kommt mit diesen Headern zurück.  Ein angenommener Handshake nicht, denn
diese 101-Antwort schreibt das Backend selbst.  Wickle also den ganzen
Baum ein, Socket eingeschlossen, statt den Socket auszuschneiden.  Siehe
[WebSocket](/de/http/websocket/).
