`FastifyBackend` ist das **Default**-HTTP-Backend für actor-ts.
Umschließt Fastify — schnell, gut gewartet, mit einem riesigen
Ökosystem an Plugins (JWT-Auth, Validierung, Swagger usw.).

```ts
import { ActorSystem } from 'actor-ts';
import { HttpExtensionId } from 'actor-ts/http';

const http = system.extension(HttpExtensionId);

await http.newServerAt('0.0.0.0', 8080).bind(routes);
//  ↑ standardmäßig Fastify
```

Um das Backend explizit zu machen:

```ts
import { FastifyBackend } from 'actor-ts/http';

await http.newServerAt('0.0.0.0', 8080)
  .useBackend(new FastifyBackend())
  .bind(routes);
```

## Konfiguration

```ts
new FastifyBackend({
  logger:    false,           // Fastifys eingebauter Logger — aus lassen; nimm actor-ts-Log
  bodyLimit: 1_048_576,       // 1 MiB Request-Body-Cap
  tls: {
    cert: fs.readFileSync('./tls/cert.pem'),
    key:  fs.readFileSync('./tls/key.pem'),
  },
});
```

`bodyLimit` ist das eine, das das Framework für dich setzt. Ohne eigene
Angabe steht es auf **1 MiB** — demselben Cap, den auch das Express- und
das Hono-Backend anwenden; welche Requests angenommen werden, hängt damit
nicht mehr vom Backend ab. Ein eigener Wert gewinnt weiterhin.

Die meisten Settings werden an Fastifys `FastifyServerOptions`
durchgereicht.  Das Framework konfiguriert die Routen-
Registrierung; du drehst an Fastifys eigenen Reglern.

## Security-Header

Jede Response, die dieses Backend schreibt, trägt
`X-Content-Type-Options: nosniff` — inklusive seines Fehler-Mappings, des
`fallback`-404 und des 413 bei zu großem Body, die keine Middleware sieht.
Ein Header aus der Response selbst gewinnt weiterhin.

Konfiguriert wird das **pro Server, nicht pro Backend** — eine Oberfläche
statt dreier:

```ts
await http.newServerAt('0.0.0.0', 8080)
  .useBackend(new FastifyBackend())
  .withSecurityHeaders(false)      // oder ein SecurityHeadersOptions-Bündel
  .bind(routes);
```

Siehe [Sicherheit](/de/http/security/).

## TLS

```ts
new FastifyBackend({
  tls: {
    cert: fs.readFileSync('./tls/cert.pem'),
    key:  fs.readFileSync('./tls/key.pem'),
    // Für mTLS:
    ca:                fs.readFileSync('./tls/ca.pem'),
    requestCert:       true,
    rejectUnauthorized: true,
  },
});
```

Standard-Fastify-TLS-Optionen.  Für die meisten Produktions-Setups
**terminiert TLS am Load-Balancer** — die App spricht intern
einfaches HTTP — aber In-App-TLS wird unterstützt, wenn nötig.

## Zugriff auf die rohe Fastify-Instanz

```ts
const backend = new FastifyBackend();
await http.newServerAt('0.0.0.0', 8080)
  .useBackend(backend)
  .bind(routes);

// Nach dem Bind ein natives Plugin über die Escape-Hatch registrieren...
await backend.withPlugin(fastifyJwt, { secret: '...' });
// ...oder für Low-Level-Hooks die rohe Fastify-Instanz erreichen:
backend.fastify.addHook('onRequest', authHook);
```

Nutze das für **Plugins, die nicht über die DSL des Frameworks
exponiert sind**:

- JWT-/OAuth-Authentifizierung.
- Request-Validierung (`@fastify/swagger`).
- CORS (`@fastify/cors`).
- Komprimierung.

Die actor-ts-DSL behandelt Routing; Fastify-Plugins behandeln
Querschnittsthemen.  Sie komponieren sauber.

## Lifecycle

```
1. new FastifyBackend() — der Konstruktor erzeugt die Fastify-Instanz
2. Das Framework registriert jede kompilierte Route bei Fastify
3. Fastify.listen() — öffnet den Port
4. Beim Shutdown: Fastify.close() — drained In-Flight-Requests, dann Exit
```

`Fastify.close()` wartet auf den Abschluss laufender Requests,
bevor es resolved — passt zur `service-unbind`-Phase des
[Coordinated Shutdown](/de/fundamentals/coordinated-shutdown/).

## Gebündelte Dependency

Fastify ist eine **feste Dependency** von actor-ts — es wird mit
dem Framework installiert, es gibt also nichts extra hinzuzufügen.
(Die Express- und Hono-Backends sind dagegen optionale
Peer-Dependencies, die du bei Bedarf installierst.)

## Performance

Grobe Zahlen für triviale Routen:

- **150K–200K req/sec** auf Bun (mit `bun:test`-Benchmark).
- **80K–120K req/sec** auf Node 22.
- **P50-Latenz** unter einer Millisekunde für triviale Handler;
  höher für Routen, die Actors fragen.

Fastify ist eines der schnellsten Node-HTTP-Frameworks; der
Actor-Routing-Overhead des Frameworks ist der nächste Bottleneck
für heiße Routen.

import { Aside } from '@astrojs/starlight/components';

<Aside type="caution" title="Nicht Fastifys Logger und actor-ts-Log zusammen nutzen">
  ```ts
  new FastifyBackend({ logger: true });   // ✗ erzeugt Rauschen
  ```
  Fastifys eingebauter Logger dupliziert das Logging von actor-ts.
  Deaktiviere Fastifys Logger; verlass dich auf `system.log` für
  strukturiertes Logging.
</Aside>

<Aside type="caution" title="Plugins, die Routen überschreiben">
  ```ts
  // Fastify-Plugin, das sich an /api/* hängt, überschreibt actor-ts-Routen
  ```
  Vorsicht bei Plugins, die Routen registrieren — sie könnten mit
  der Routen-Registrierung des Frameworks kollidieren.  Registriere
  Plugins **vor** dem Binden der actor-ts-Routen, wenn beide auf
  überlappende Pfade zielen.
</Aside>
