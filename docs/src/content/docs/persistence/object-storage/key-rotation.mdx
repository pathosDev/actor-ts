For object-storage encryption, the master key needs to rotate
periodically (security policy, compromise response, compliance).
The framework supports **online rotation** — zero downtime, old
data readable throughout.

The flow:

```
   1. Generate a new key.  Add it to the keyring as `active`; keep the old one under `retired`.
   2. Roll out.  New writes encrypt under `active`; old payloads decrypt via `retired`.
   3. Run the re-encryption sweep.  Old payloads → the active key.
   4. Wait the rollback window (~7 days) — backups may still reference the old key.
   5. Drop the `retired` entry from the keyring.  Cleanup.
```

This page covers the **store-side mechanics**; for the operational
walkthrough see
[Master key rotation (operations)](/operations/security/master-key-rotation/).

## The keyring

Encryption keys live in a `MasterKeyRing` — an `active` key for
new writes plus any `retired` keys still needed to decrypt older
payloads.  Each entry pairs a numeric `version` (embedded in the
payload manifest) with the 32-byte AES-256 key:

```ts
import type { MasterKeyRing } from 'actor-ts';

const keyring: MasterKeyRing = {
  active:  { version: 2, key: newKey },       // new writes use this
  retired: [{ version: 1, key: oldKey }],     // still decrypts old payloads
};
```

## The sweep

```ts
import { reEncryptObjectStorage } from 'actor-ts';

const result = await reEncryptObjectStorage(backend, {
  keyPrefix: 'snapshots/',                      // which keys to process
  keyring,                                      // active + retired keys
  skip: (key) => key.endsWith('.manifest'),     // optional: exclude keys
  onProgress: (e) => console.log(`${e.index}/${e.total} ${e.key}`),
});
console.log(`re-encrypted ${result.rewrote} of ${result.scanned}`);
```

The sweep lists every object under `keyPrefix`, and for each one:

1. Reads it; if it's already at the **active** version, skips it
   (the idempotent fast-path — no PUT).
2. Otherwise decrypts it with the matching `retired` key and
   re-writes it under the `active` key.

It returns a `ReEncryptResult`: `{ scanned, rewrote,
skippedCurrent, skippedUnencrypted, skippedNonAts1 }`.

## Idempotent + resumable

Re-running is safe: an object already at the active version is
skipped without a write.  A plain re-run re-lists and re-checks
every key (fine for small buckets).  For million-object stores,
pass a **progress store** so a crashed sweep resumes near where it
stopped instead of re-scanning from the start:

```ts
import { InMemoryReEncryptProgressStore } from 'actor-ts';

await reEncryptObjectStorage(backend, {
  keyPrefix: 'snapshots/',
  keyring,
  progress: new InMemoryReEncryptProgressStore(),   // or a durable store
});
```

## Partial rotation with `skip`

`skip(key) => boolean` **excludes** matching keys — the inverse of
a filter.  Process a subset by skipping everything else:

```ts
await reEncryptObjectStorage(backend, {
  keyPrefix: 'state/',
  keyring,
  skip: (key) => !key.startsWith('state/account-'),   // only account-*
});
```

Useful for per-tenant, per-actor-type, or phased rotations.

## Keyring-completeness pre-check

By default the sweep samples the first encrypted objects and
**refuses to start** if any payload's key version is missing from
the keyring — catching the "operator dropped the retired key too
soon" footgun *before* a mid-sweep decrypt failure leaves the
corpus half-rewritten.  Disable with `verifyKeyringCompleteness:
false` only if you have independent assurance the keyring is
complete.

## Confirming completion

Read the returned counts — a complete sweep has `scanned ===
rewrote + skippedCurrent + skippedUnencrypted + skippedNonAts1`,
and a *second* run reports `rewrote === 0`:

```ts
const result = await reEncryptObjectStorage(backend, { keyPrefix: 'state/', keyring });
if (result.rewrote === 0) {
  // everything is already at the active key — safe to plan retiring the old one
}
```

There is no separate "list stragglers" helper; the counts are the
source of truth.

## After the sweep

Once every payload is re-encrypted **and** the rollback window has
passed, drop the `retired` entry:

```ts
const keyringAfterRotation: MasterKeyRing = {
  active: { version: 2, key: newKey },   // retired[] removed
};
```

Wait the rollback window (typically 7 days) first — backups may
still reference the old key.

import { Aside } from '@astrojs/starlight/components';

<Aside type="caution" title="Dropping a retired key too soon">
  Remove a `retired` entry only after the sweep reports every
  object at the active version *and* the rollback window has
  passed.  A payload whose key is no longer in the ring is
  unreadable — the completeness pre-check guards the *start* of a
  sweep, not your own keyring edits afterward.
</Aside>

<Aside type="caution" title="Failures stop the sweep — they aren't swallowed">
  ```ts
  // a decrypt error or backend fault bubbles up and aborts the sweep
  ```
  Per-object failures are not swallowed; the sweep stops at the
  first one.  Fix the cause and re-run — already-rewritten objects
  are idempotently skipped on the next pass.
</Aside>

<Aside type="caution" title="Concurrent write during the sweep">
  ```ts
  // app writes an object the sweep is rewriting → ETag mismatch
  ```
  The sweep writes with a compare-and-set on the object's ETag.
  If the app wrote a newer version first, the CAS fails and the
  sweep throws `ObjectStorageConcurrencyError` and aborts — re-run
  it (the freshly-written object is already current and is skipped).
</Aside>
